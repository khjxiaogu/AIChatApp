# AI 群助手 用户说明书

> 适用对象：群成员与私聊用户  
> 版本：2026 年 11 月

AI 群助手是一套挂在 QQ 群和私聊里的智能助手。在群里 @ 它就能提问；私聊它，就像有一位专属助理，可以查资料、看截图、记笔记，也可以把明确的开发需求交给它处理并跟踪结果。你不需要安装软件，也不需要做任何配置。

## 一、它由哪些角色组成

| 角色 | 在哪里 | 负责什么 |
|---|---|---|
| 群助手 | 每个群一个 | 了解本群上下文，负责群内答疑、资料查询、把合适的开发需求整理出来 |
| 私人助手 | 每位用户一个 | 一对一服务你，能记住你的偏好，接收并跟踪你提交的任务 |
| 专业助手 | 后台 | 真正执行代码修改、构建、绘画、语音等具体工作，由前两类助手转交 |
| 管理员 | 后台 | 开通能力、处理敏感操作审批；普通用户无需接触 |

协作方式很简单：你向群助手或私人助手提出需求，它们判断该自己做还是转给专业助手，拿到结果后再回复你。

三条基本原则：

- 群聊是公开的，私聊是私密的。
- 助手只服务当前会话，不会把你的私聊内容带到群里，也不会把别人的私聊告诉你。
- 群助手可以“看情况沉默”，不是每句话都接。

## 二、能做什么

| 能力 | 你可以这样说 | 说明 |
|---|---|---|
| 日常问答 | “这个功能怎么用？”“帮我改一段文案” | 解释、建议、写作、翻译、总结都可以 |
| 查资料 | “看看这个链接说了什么” | 读取网页、百科与搜索结果（视开通情况） |
| 看图 | “这张报错图是什么问题？” | 识别截图、报错、界面和图片内容 |
| 群内回顾 | “刚才群里聊了什么？” | 可检索本群最近的消息，默认只记得少量上下文 |
| 项目知识库 | “找一下关于登录流程的设计文档” | 查询项目文档、设计、日记、讨论记录，并给出来源 |
| 个人笔记 | “记一下：以后回答简短些” | 仅私聊可用，只对自己可见，之后可查、可改 |
| 编程任务 | “修复登录页点提交没反应的问题” | 由编程助手改代码、构建、验证，完成后汇报 |
| 多媒体 | “发一张表示赞的图”“把这段读出来”“画一只猫” | 发图、表情、语音、音乐、绘画、视频等，视开通情况 |
| 协作 | 助手主动发选项卡片；“这事让编程助手跟进” | 点按钮或回复编号；转接只传摘要，不转完整聊天记录 |

不同群、不同用户开通的能力可能不同，以实际可用为准。没有开通的能力，助手会直接说明，而不会假装能做。

## 三、总体使用方法

上手只需三步：在群里 @ 助手，或直接私聊它；直接说需求，可以附截图、报错文字或链接；按它的追问或选项补充信息，等结果。

### 3.1 在群里使用

- @ 助手后直接提问，一句话说清“做什么、在哪、希望怎样”。
- 连发几条、多人同时 @ 时，助手会等约 2 秒把消息合并起来看，不必重复 @。
- 没被 @ 时，它只在话题与它直接相关时接话；普通闲聊一般不插嘴。
- 有的群设置为“只有 @ 才回复”，有的群会在讨论较多时集中看一次、统一回复。
- 群内回复通常比较简短，细节可以继续追问，或转到私聊。

### 3.2 在私聊中使用

- 不用 @，直接发消息即可。
- 多数部署会自动开通私聊；若提示未开通，请联系管理员。
- 私聊消息会逐条处理，建议一次把需求说完整，避免只发“在吗”“搞一下”。
- 私聊内容不会发到群里，除非你明确要求它转达。

### 3.3 怎样提问更有效

推荐按这个顺序说：

- 背景：在哪个项目、页面或场景。
- 现象：发生了什么，期望是什么。
- 已尝试：你试过哪些办法。
- 结果标准：怎样算完成。

例如：

> 登录页点“提交”没反应，Chrome 控制台报 `xxx`，希望修好后能正常跳转，并告诉我怎么验证。

比“登录坏了，修一下”更容易一次做对。

### 3.4 提交编程任务

1. 在私聊里说明：哪个项目或功能、现在什么现象、希望改成什么、怎样算完成。
2. 助手会先确认需求；完全看不出目标时会追问一句，不会替你猜。
3. 任务在后台执行，可以先做别的事；需要时问“进度怎么样”，或让它“停一下”。
4. 完成后它会说明：做了什么、改了哪些文件、怎么验证，一般不贴大段代码。
5. 遇到敏感操作，它会私聊你或管理员确认。回复数字即可：1 允许这一次，2 允许并记住本会话，3 拒绝，4 拒绝并终止本次任务；支持卡片时也可以直接点按钮。

### 3.5 发图片和文件

- 直接把图片发给助手，再补一句你想问什么，比只发图更准确。
- 网页、日志、文档优先发链接或粘贴文本，避免超大附件。
- 发送的图片会被助手读取，用于理解和回答。

### 3.6 让它记住你的偏好

在私聊里说“记一下：……”，例如“记一下：以后回答尽量简短”“记住我的项目是……”。之后说“按之前记的来”即可。记错了就说“把刚才那条改成……”或“忘掉……”。个人笔记只对自己可见。

### 3.7 把需求转给合适的助手

不确定该找谁时，直接说“这个让编程助手跟进”。助手会把必要的摘要交给对方，不转完整聊天记录；之后由接手的助手继续回复你。

## 四、交互规则

- 群里只有被 @ 时一定回复；其他消息是否接话，取决于群设置和话题相关性。
- @ 之后会短暂等待并合并消息；群里讨论较多时会成批处理，所以不一定秒回。
- 长任务通常先回一句“收到”，完成后再汇报，不会全程刷屏。
- 助手不会编造结果：没拿到执行结果，就不会说“已完成”。
- 群内回复一般控制在几百字内；私聊可以稍长。
- 助手不会主动私聊无关用户，也不会把你的私聊转发给别人。

## 五、隐私与安全

- 群聊内容所有人可见。账号、密码、密钥、身份证、私人聊天截图不要发到群里。
- 私聊只属于你和助手；转接时也只传递摘要。
- 审批请求只会发给本人或管理员。
- AI 可能出错。重要结论请复核；涉及金钱、法律、医疗等事项，请咨询专业人士。
- 生成的文字、图片请自行确认版权与合规。
- 不要用助手从事违法、侵权、骚扰或泄露他人隐私的行为。

## 六、常见问题

**为什么 @ 了没反应？**  
可能尚未开通、上一轮还在处理、消息被合并，或平台网络波动。稍等后重新 @ 一次；仍无响应请联系管理员。

**为什么回得慢？**  
群消息在合并，或任务在排队、执行中。长任务需要时间，完成后会主动汇报。

**它会记得群里说过的话吗？**  
每个群有独立上下文，默认只保留最近少量消息；需要更早的内容时，可以让它查本群最近记录。私聊默认不读取群聊。

**我的私聊会被别人看到吗？**  
不会。只有你和助手可见；转给其他助手时只传摘要。

**它能踢人、禁言或发群公告吗？**  
一般不具备群管理权限，只负责对话和任务。

**任务做到一半能停吗？**  
可以，直接说“停一下”或“取消这个任务”。

**它说完成了，但我没看到变化？**  
让它给出改动文件和验证方式；仍有疑问可请管理员复查。

**换号后记录还在吗？**  
记录按账号区分，换号相当于新用户。

## 七、使用建议

- 一次一件事，把背景、现象、期望说清楚。
- 给出可验证的完成标准，比如“页面能正常跳转”“构建通过”。
- 大任务拆成小步，逐步确认。
- 重要结论可以让它记进个人笔记，方便以后查。
- 反馈问题时带上截图、报错原文和时间，定位更快。

## 八、能力边界

- 助手不是万能的，不能替代人工判断与最终审核。
- 不保证实时响应，高峰期需要排队。
- 部分能力需要管理员开通，未开通时无法使用。
- 服务时间、使用额度由管理员设定。
- 平台自身也可能有限制，例如私聊连续互动过多时回复会延迟或被限制。

## 九、一页速查

| 我想…… | 这样做 |
|---|---|
| 问一个问题 | 群里 @ 助手，或私聊直接问 |
| 让它看报错 | 发截图 + 一句“帮我看看这个问题” |
| 查项目资料 | “找一下关于……的文档” |
| 让它记住偏好 | 私聊“记一下：……” |
| 提交开发任务 | 私聊说明项目、现象、期望、完成标准 |
| 看任务进度 | “进度怎么样？” |
| 停止任务 | “停一下”或“取消任务” |
| 换一个助手处理 | “让编程助手跟进” |
| 确认敏感操作 | 回复 1/2/3/4，或点卡片按钮 |
| 反馈问题 | 带上截图、报错原文、时间，发给管理员 |
