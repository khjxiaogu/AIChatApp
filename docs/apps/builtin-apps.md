# 8 种内置类型：玩法与文件要求

`meta.json` 里的 `type` 只能是这 8 个之一。每种类型能做什么、需要哪些文件、输出格式长什么样，都在这里。
（想新增第 9 种就得改代码：[docs/dev/java-api.md](../dev/java-api.md)。）

| 类型 | 界面显示名 | 用哪个页面 | 一句话 |
|---|---|---|---|
| `talk` | 你在 meta 里写的 `name` | `galgame.html` | 立绘角色对话，剧情 + 场景标签 + 语音 |
| `galgame` | 同上 | `ptrpg.html` | 多幕剧叙事，玩家用自然语言行动 |
| `trpg` | 同上 | `trpg.html` | 跑团：场景 + 多角色立绘 + 标签校验 |
| `group` | 同上 | 无（QQ 群） | 群聊机器人 |
| `wuxia` | 武侠模拟器 | 无现成页面 | 修仙/武侠模拟，属性面板驱动 |
| `write` | 写作 | 无现成页面 | 先出大纲再写正文 |
| `sql` | sql | 无现成页面 | 根据表定义生成 SQL |
| `custom` | 自定义智能体 | `custom.html` + `agentedit.html` | 网页上现配现用的智能体 |

> ⚠️ 页面文件名和类型**不对应**：`galgame.html` 服务 `talk` 类型，`galgame` 类型反而用 `ptrpg.html`。
> 判断依据是"应用ID 怎么拼"（见每节开头），不是文件名。

---

## `talk` — 角色对话

**玩法**：左侧立绘 + 背景，AI 用角色口吻演舞台剧；可开语音朗读、切模型、撤回/重说、导出对话与记忆、多存档。

**打开方式**：`aigal?chara=<X>&uid=<你的ID>` → 应用ID = **`X` + `talk`**。
例：`aigal?chara=fengxi` 打开的是 `fengxitalk`。

**必需文件**：`role.txt`、`charaset.txt`、`rules.txt`、`summary.txt`、`prelogue.txt`

**可选文件**

| 文件 | 作用 | 不提供会怎样 |
|---|---|---|
| `validator.json` | 场景标签白名单 | 不校验，模型写什么就收什么 |
| `chara.json` | 立绘选择规则 | 没有立绘 |
| `back.json` | 背景选择规则 | 没有背景 |
| `replacements.json` | 朗读前的文本替换（如去掉 `（动作）`） | 语音会把括号内容念出来 |

**输出格式**（标记必须独占一行）

```
==对话==
（角色名）台词、旁白……
==场景==
地点=街道
时间=上午
表情=微笑
位置=前
```

- `==场景==` 的键值**不显示给玩家**，只用来选立绘/背景、并作为下一轮的状态；
- `位置=前` → 正面立绘，`位置=侧` → 侧面立绘，填别的（如 `不在身边`）→ 不显示立绘；
- 显示给玩家的只有 `==对话==` 下的正文。

**注意**

- 格式写坏、或 `==场景==` 全被白名单丢掉时，程序会**自动重问**（最多 8 次），很费额度；
- `validator.json` 存在时是**白名单**：新增标签必须同步加进去，否则被静默丢弃；
- 模型一次回复的字数上限不高，而 `==场景==` 在正文之后——**回复太长会被截断**，从而触发重问。
  在 `rules.txt` 里加字数限制能明显减少重问；
- 场景值里不能出现 `=`（会被整行丢掉）。

## `galgame` — Galgame 风格叙事

**玩法**：背景 + 多幕剧文本，玩家用自然语言描述行动，AI 给出"你选择 / 情景剧本 / 操作选项"。

**打开方式**：`ptrpg?chara=<应用ID>&uid=<你的ID>`（这个页面直接拿 `chara` 当应用ID）。
系统首页没有列它，需要自己拼网址。

**必需文件**：`prompt.txt`、`charaset.txt`、`summary.txt`、`init.txt`

- `init.txt` = 开局自动发送的第一句"玩家输入"（命名完成后立即触发首轮）；
- `prompt.txt` 里写核心规则与格式；
- ⚠️ 这个类型**缺文件会直接加载失败**（应用消失），不像其他类型"带病运行"。

**meta 私有字段**：`background`（进入/重连时显示的默认背景图）。

**输出格式**

```
你选择：（概括玩家刚才的操作）
==情景剧本==
A市，上午，晴。
【角色】「台词」
（神态动作）
==操作==
1. ……
2. ……
```

- 文末会自动补一行"选择你的操作（数字或行动）："；
- 选项**不会**被程序重新编号（除非模型漏掉了 `==情景剧本==` 段），所以让模型自己写好编号。

**注意**

- 格式坏了不会重问，只把用户输入退回输入框（省钱但也不再自动纠正）；
- 没有立绘、没有语音、没有数值校验。

## `trpg` — 跑团

**玩法**：场景 + 多角色立绘 + 对白，支持撤回/重说/导出。

**打开方式**：`aitrpg?chara=<X>&uid=<你的ID>` → 应用ID = **`X` + `trpg`**。

**必需文件**：`role.txt`、`charaset.txt`、`rules.txt`、`summary.txt`、`prelogue.txt`

**可选文件**：`validator.json`（同时校验场景段和角色段）、`chara.json`、`back.json`

**输出格式**

```
==场景==
地点=教室
时间=上午
天数=1
==对话==
【角色名】「台词」
（行动）
==角色==
小雪表情=微笑
小雪位置=前
```

- `==角色==` 段里离场的角色必须写 `位置=不在`，否则它会一直保留上次的表情和站位；
- `位置=前` / `位置=侧` 决定站在哪一排，支持多个角色同时显示；
- 场景和角色的键值**跨轮累积、不会自动清空**（规则要求"不确定时沿用上次"）。

**注意**

- 场景值必须落在 `rules.txt` 声明的枚举里，且和 `validator.json` 一致，否则选不到图；
- 角色名的解析依赖"表情/位置"这两个后缀，**键名要用 `<角色名>表情`、`<角色名>位置`**；
- 格式坏会自动重问（最多 5 次）；
- 长对话压缩时会额外调一次模型做摘要，那一轮会明显变慢。

## `group` — QQ 群机器人

**玩法**：机器人挂在 QQ 群里，@ 它就对话。**没有网页**。

**在哪里配**：`save/config/agents.json` 列出"哪个应用目录 × 哪个群 × 哪个存档文件"，
然后用 NapCat 相关启动参数拉起（见 [configuration.md §6](configuration.md#6-启动参数)）。

**必需文件**：`role.txt`、`charaset.txt`、`rules.txt`、`summary.txt`

**meta 私有字段**：`charaName`（**必需**，机器人在群里的自称；缺失 → 加载失败）。

**输出格式**：没有标记，纯文本。群聊要短——在 `rules.txt` 里限制字数和行数。

**注意**

- 群消息为空（纯 @、纯表情）时不会写进历史；
- 模型正文为空时会退而从"思维链"里找回复，所以思维链里别放不该发出去的内容；
- 想同时有网页和群聊？建两个应用目录（不同 `type`），各自写提示词。

## `wuxia` — 修仙 / 武侠模拟

**玩法**：纯文本回合制。首次进入给 2 男 2 女候选名（可"换一批"），取名后开始；
每轮 AI 产出「大纲 → 情景剧本 → 属性面板 → 操作选项」，玩家选编号或自己写行动。

**界面显示名**：武侠模拟器（改 `meta.name` 不会改这个）。

**打开方式**：**目前没有现成网页**（它原来用的页面已从仓库移除）。
想玩只能自己配一个 `custom` 智能体复刻格式，或走接口/桌面端。

**必需文件**：`prompt.txt`（核心规则 + 五段格式）、`name-male.txt`、`name-female.txt`（名字库）
——名字库**至少各 2 行**，否则取名会卡住。

**输出格式**

```
你选择：
==故事大纲==
1. ……
==情景剧本==
（正文，很长）
==属性面板==
【主角面板】
【姓名】叶凡
【境界】炼气三层
【灵石】120
……
【队友面板】
【姓名】……
==操作==
1. ……
```

- 面板解析：`【X面板】` 开块，块内每行 `【属性名】值`；
  主角面板和队友面板各有固定的默认属性项，模型没写的项保留上一轮的值；
- `==故事大纲==` 之后的内容会进上下文，但**不显示给玩家**；
- 属性有变化的回合支持"撤回后数值一起回滚"。

**注意**

- 面板块头用 `【…面板】` 正则匹配，**队友名字里带"面"字会解析失败**；
- 属性行必须写成 `【键】值` 且值非空，否则该属性保持旧值；
- 每轮会往用户消息里追加固定要求（"至少 5 条大纲…1500 字"），这会一直留在历史里，费额度；
- 提示词里出现的"输入『重新生成』"是桌面端遗留文案，**网页上不生效**（网页要用页面按钮）。

## `write` — 写作辅助

**玩法**：给写作要求，AI 先出大纲再写正文；`查看大纲` 可回看已生成的大纲。

**界面显示名**：写作。**打开方式**：目前没有现成网页。

**必需文件**：只有 `prompt.txt`（约定 `==大纲==` / `==内容==` 两段）。

**注意**

- `==大纲==` 段只进上下文、不显示；`==内容==` 这个标记行会被丢弃；
- **不做长对话压缩**：写长篇最终会把上下文撑爆，需要手动开新对话接续；
- 会话标题取大纲的前几个字，模型没写大纲时标题可能异常。

## `sql` — SQL 生成

**玩法**：先用 `定义 <建表语句>` 累积表结构，再提问，AI 输出解释 + SQL。

**界面显示名**：sql。**打开方式**：目前没有现成网页。

**必需文件**：`prompt.txt`。

**注意**

- 样例 `prompt.txt` 要求模型输出 `=====SQL=====`，而程序找的是 `==SQL==`，两者**对不上**——
  结果只是标记行会显示出来，不影响回答内容。想干净就统一把 prompt 里改成 `==SQL==`；
- `定义` 是前缀匹配：任何以"定义"开头的话都会被当成表定义吞掉，提问时避开这两个字开头；
- 该应用的历史列表名固定显示为一小段常量，容易混淆，建议手动重命名对话。

## `custom` — 配置型智能体

**玩法**：在 `agentedit` 页面填四个栏位，保存即得一个独立智能体；随时可以回来改，不用重启。

**打开方式**：`custom?chatid=<对话ID>`（编辑器在 `agentedit`）。

**必需文件**：全站共用一个 `save/apps/custom/` 目录，里面两个文件**都不能删**：

| 文件 | 作用 |
|---|---|
| `summary.txt` | 长对话压缩指令；缺了 → `custom` 应用加载失败 |
| `prompt.txt` | 新建智能体时的默认核心规则；缺了 → **整个服务起不来** |

**输出格式**：**程序不解析任何标记**，完全由你写的核心规则决定。

**注意**

- 最自由也最容易格式失控——没人帮你兜底，写法见 [prompting.md](prompting.md)；
- 长对话压缩会同步调一次模型（可能要重试多次），那一轮明显变慢；
- 提示词存在**对话存档**里，所以每个智能体互不影响；导出/迁移时要连同存档一起搬。
