# 教程：不动代码，做出你自己的 AI 应用

这套教程**不需要写任何代码**。所有 app 都是「一个目录 + 几个文本文件」，
改完重启服务就生效。

三个练习，从易到难，一共约 40 分钟：

| 练习 | 做什么 | 难度 | 需要重启 | 耗时 |
|---|---|---|---|---|
| [一](#sec-ex1) | 用网页表单造一个「赛博算命先生」 | ★ | 不需要 | 5 分钟 |
| [二](#sec-ex2) | 复制现成角色，改成你自己的角色 | ★★ | 需要 | 15 分钟 |
| [三](#sec-ex3) | 做一个带属性数值的武侠冒险 | ★★★ | 需要 | 20 分钟 |

> 术语先记三个词：**应用目录**（`save/apps/<应用ID>/`）、**应用ID**（就是目录名）、
> **提示词文件**（目录里的 `.txt`，决定 AI 怎么说话）。详见 [files.md](files.md)。

## 练习一：用网页做一个智能体（最快）

**适合**：只想让 AI 扮演某个角色/专家，一个脑子一件事。

### 1. 打开编辑器

浏览器访问 `http://你的地址:8999/aichat/agentedit`
（首页「自定义agent」也是这个页面）。

### 2. 填四栏

| 栏位 | 填什么 | 上限 | 建议 |
|---|---|---|---|
| 名称 | 赛博算命先生 | 20 字 | 会变成对话标题 |
| 核心规则 | 见下 | 5000 字 | 写"绝对不能做什么"和"输出格式" |
| 游戏设定 | 见下 | 8000 字 | 写世界观、身份、背景 |
| 上下文上限 | 60000 | 30000~100000 | 默认即可，聊得长再调大 |

**核心规则**（直接抄，改成你的风格）：

```
你是一位「赛博算命先生」，用电子玄学给人算命。

【输出格式】每轮回答必须包含三段，缺一不可：
你选择：<一句话概括用户刚才的提问>
==卦象==
<用 ASCII 字符画一个 5 行以内的卦象/电路图>
==解读==
<120 字以内的解读，用一个建议收尾>

【硬性规则】
1. 不预测生死、疾病、法律结果，涉及这些时回答"此卦不可测"。
2. 每轮至少出现一个电子/网络词汇（如"数据""算法""带宽"）。
3. 不要解释你在扮演角色。
```

**游戏设定**：

```
世界背景：2077 年的旧城区，霓虹与雨。你是这条街上唯一还在营业的算命摊，
摊位上摆着一台老式终端。来算命的人多是走投无路的年轻人。
你的说话风格：慢、简短、偶尔用技术比喻讲命理。
```

### 3. 保存并打开

点保存 → 页面会给出「开始对话」，新标签页打开就是对话页。

先随便问一句，检查：**AI 有没有按三段格式回答**？
如果只有一段、或者把 `==卦象==` 当成普通文字念出来，就是提示词的格式契约没写严，
照 [prompting.md](prompting.md) 的"格式契约"一节加强。

### 4. 随时改

回到 `agentedit?chatid=<那个对话的ID>` 可以继续编辑——**不用重启**。
每个智能体是独立的对话，互不影响；想做第二个就新建。

> 练习一的产物存在对话存档里（`save/saveData/<chatid>.json`），不占应用目录。

## 练习二：复制一个角色对话应用

**适合**：要一个有立绘、有背景、能读出来的角色（`talk` 类型）。

### 1. 复制模板

```bash
# Linux / macOS
cp -r save/apps/fengxitalk save/apps/mydetective
# Windows PowerShell
Copy-Item -Recurse save\apps\fengxitalk save\apps\mydetective
```

**应用ID = 目录名 = `mydetective`**。这个值一旦定了别改，改了已有存档就对不上了。

### 2. 改 `meta.json`

```json
{
  "type": "talk",
  "name": "我的侦探",
  "enabled": true,
  "access": "public"
}
```

- `type` **绝对不能改**（它决定用哪套逻辑），照抄 `talk`；
- `name` 是加载所必需的（也是这个角色的名字），但界面上显示的名字来自程序内部；
- `access`：`public` 所有人可见，`permission` 需要授权，`hidden` 不出现。详见 [configuration.md](configuration.md)。

### 3. 改四个提示词文件

打开 `save/apps/mydetective/`，逐个改（**保持 UTF-8 编码，不要带 BOM**）：

| 文件 | 改什么 | 不改会怎样 |
|---|---|---|
| `role.txt` | 角色身份、怎么说话、自称 | AI 还是原来的角色口吻 |
| `charaset.txt` | 详细设定：年龄、经历、关系、口头禅 | 角色扁平、容易崩设定 |
| `rules.txt` | **输出格式**（`==对话==` / `==场景==` 那两段） | **千万别大改格式段**，改了会让程序解析失败 |
| `prelogue.txt` | 第一次见面时的开场白 | 开场白还是原来的 |
| `summary.txt` | 长对话的压缩指令 | 一般不用改，多个角色可共用 |

`rules.txt` 里必须保留这段骨架（内容可以改写，标记不能改）：

```
==对话==
（角色名）台词、旁白……
==场景==
地点=街道
时间=上午
表情=微笑
位置=前
```

### 4. 场景标签与立绘

`==场景==` 下面的键值不是给玩家看的，是给程序"选图"用的：

- `位置=前` → 正面立绘；`位置=侧` → 侧面立绘；填别的值 → 不显示立绘；
- `地点`/`时间`/`表情` 等要和 `back.json`、`chara.json` 里的条件对得上才选得到图；
- 如果目录里有 `validator.json`，它是一份**白名单**：模型写了不在名单里的键会被丢弃。
  默认的 `validator.json` 只认「地点/时间/季节/表情/服装/位置/星期」，
  你的 `rules.txt` 里若新增了别的标签，必须同步加进 `validator.json`，否则会被静默丢掉。

> 没有美术资源？把 `chara.json`、`back.json` 删掉即可，页面就只显示文字，其他一切正常。

### 5. 重启并验证

重启服务，看日志有没有这一行：

```
AI加载成功：mydetective
```

然后按页面的命名规则打开。**这条规则很容易踩**：`galgame.html` 会把网址里的 `chara`
参数加上 `talk` 后缀当应用ID：

```
aigal?chara=mydetective&uid=test   →   找的是应用ID "mydetectivetalk"
```

所以要么把目录名改成 `<chara>talk`（例如 `mydetectivetalk`），要么在网址里用对应的写法。

进入后依次确认：能弹姓名输入 → 开场白出现 → 回复里台词显示正常、立绘按 `位置` 切换。

### 6. 常见不满意 → 改哪儿

| 现象 | 改哪里 |
|---|---|
| 说话太长/太短 | `rules.txt` 加一条字数限制 |
| 总说现代词、崩人设 | `charaset.txt` 补"禁止…"清单；`rules.txt` 加语气示例 |
| 立绘不换 | 检查 `位置=` 的值、`chara.json` 的条件、`validator.json` 白名单 |
| 背景不对 | 检查 `地点`/`时间` 与 `back.json` 条件 |
| 语音念出括号里的动作描写 | 在 `replacements.json` 里加一条正则把 `（…）` 换成空 |

## 练习三：做一个文字冒险应用

**适合**：要数值、要选项、要长剧情（`trpg` 类型，能显示多角色立绘）。

### 1. 复制模板

```bash
cp -r save/apps/xinghantrpg save/apps/mywuxia
```

（也可以复制 `save/apps/fengyidlc` 做纯文字版 `galgame`。）

### 2. 改 `meta.json`

```json
{
  "type": "trpg",
  "name": "我的江湖",
  "enabled": true,
  "access": "public"
}
```

### 3. 写 `rules.txt`——这是最关键的一步

`rules.txt` 要同时承担两件事：**教 AI 怎么玩** 和 **约定输出格式**。骨架必须保留：

```
你在进行一个武侠文字冒险，玩家扮演主角。
每轮你必须输出三段，顺序固定，标记独占一行：

==场景==
地点=<当前地点，只能是：客栈|山道|城镇|密室>
时间=<上午|下午|夜晚>
天数=<从1开始递增的整数>
==对话==
【角色名】「台词」
（动作/环境描写）
==角色==
<角色名>表情=<微笑|愤怒|忧伤|冷漠>
<角色名>位置=<前|侧|不在>
```

要点：

1. **枚举值要写死**（`只能是：客栈|山道|城镇|密室`）。这些值同时要写进 `validator.json`
   的白名单，否则会被丢掉；
2. `==角色==` 段里离场的角色必须写 `位置=不在`，否则它会一直保留上一次的表情和站位；
3. 每一段之间**不要**加别的装饰（代码块、分隔线），程序是按行解析的。

### 4. 写 `charaset.txt` 和 `role.txt`

- `charaset.txt`：世界观、门派、NPC 关系、主角初始处境。越长越稳，但每轮都会发给模型；
- `role.txt`：一句话说明"你在扮演什么"，放系统提示最前面；
- `prelogue.txt`：开场白（取名完成后显示）。

### 5. 同步 `validator.json`

打开模板里的 `validator.json`，把你在 `rules.txt` 里写的枚举值照抄进去。
格式是「键的匹配 + 允许的值」：

```json
{
  "rules": [
    { "keyPattern": "地点", "valuePatterns": ["客栈", "山道", "城镇", "密室"] },
    { "keyPattern": "时间", "valuePatterns": ["上午", "下午", "夜晚"] },
    { "keyPattern": "天数", "valuePatterns": ["[0-9]+"] },
    { "keyPattern": ".*表情", "valuePatterns": ["微笑", "愤怒", "忧伤", "冷漠"] },
    { "keyPattern": ".*位置", "valuePatterns": ["前", "侧", "不在"] }
  ]
}
```

> 不确定就先**删掉** `validator.json`：不校验 = 全部接受（但模型写错也不会被抓出来）。
> 等格式稳定了再加回来。

### 6. 重启并验证

日志出现 `AI加载成功：mywuxia`，然后打开：

```
aitrpg?chara=mywuxia&uid=test    →   找的是应用ID "mywuxiatrpg"
```

（同样注意后缀规则：`trpg` 页面会把 `chara` 加上 `trpg`。）
若想让它用 `ptrpg` 那个页面，用 `ptrpg?chara=<应用ID>&uid=test`，它是直接拿 `chara` 当应用ID。

依次确认：姓名流程走得通 → 首轮出现场景/对白/选项 → 立绘按角色出现 →
再玩两轮，确认 `地点`/`天数` 这类值每轮都在变。

### 7. 调整数值与节奏

- 想让 AI 报属性（血量/好感）：在 `rules.txt` 里加一段「属性面板」格式，
  但注意 `trpg` 类型只解析「场景」和「角色」两段，额外段会当普通正文显示；
- 想压缩更频繁/更省额度：`summary.txt` 写清摘要要求即可（阈值是程序固定的）；
- 想限制选项数量、禁止自创地名：都写进 `rules.txt` 的硬性规则，越具体越稳。
